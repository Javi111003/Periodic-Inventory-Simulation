\section{Introducción}
Imagina que tienes una pequeña tienda de tu producto estrella —pongamos camisetas de edición limitada— y cada día llegan clientes de forma impredecible: algunos compran una sola prenda, otros varias de golpe. Si no tienes suficiente stock, pierdes ventas y, con ellas, clientes habituales. Pero si pides demasiado y lo guardas en el almacén, incurres en gastos de espacio y capital inmovilizado.

Para gestionar esta incertidumbre, adoptas una política sencilla: fijas un umbral mínimo $s$ y, cuando tu inventario baja de ese punto, haces un pedido para reponer hasta un nivel $S$. Cada pedido tiene un coste que depende de cuántas unidades pidas, y tarda un tiempo $L$ en llegar. Además, mantener cada camiseta en estantería te cuesta $h$ unidades monetarias por día, y las vendes a un precio $r$.

Con simulación de eventos discretos podemos recrear este escenario una y otra vez, permitiéndonos evaluar distintas políticas de inventario bajo incertidumbre y encontrar estrategias que equilibren la rentabilidad con el nivel de servicio al cliente.

En la gestión moderna de inventarios, mantener el equilibrio entre nivel de servicio y costos es esencial. Un exceso de stock genera altos costos de almacenamiento y capital inmovilizado, mientras que un inventario insuficiente conlleva pérdidas de ventas y de fidelidad de clientes. Este proyecto aborda el clásico \emph{modelo de inventario $(s,S)$} descrito por Ross \cite{ross2013simulation}, implementado mediante simulación de eventos discretos, para estimar la ganancia promedio y otras métricas relevantes bajo incertidumbre estocástica.

\subsection{Objetivos y metas}
\begin{itemize}
  \item Implementar un simulador de eventos discretos del modelo $(s,S)$ para un único producto.
  \item Estimar la ganancia promedio por unidad de tiempo en un horizonte $T$.
  \item Identificar la política óptima $(s^*,S^*)$ que maximiza la ganancia esperada.
  \item Analizar la sensibilidad de las métricas ante variaciones en la tasa de demanda $\lambda$ y el tiempo de entrega $L$.
  \item Evaluar el impacto de distintas distribuciones de demanda y estructuras de costo de pedido.
  \item Cuantificar la incertidumbre de los resultados mediante bootstrap.
\end{itemize}

\subsection{Sistema específico a simular}
Simulamos una tienda que vende un producto a precio unitario $r$. Las llegadas de clientes siguen un proceso de Poisson con tasa $\lambda$, y cada cliente demanda una cantidad aleatoria $D\sim G$. Se adopta una política $(s,S)$: cuando el inventario cae por debajo de $s$ y no hay pedidos pendientes, se ordenan $S-x$ unidades, con costo $c(y)$ y lead time $L$. El costo de mantenimiento es $h$ por unidad y por unidad de tiempo. Si $D>x$, se vende $x$ y se pierde $D-x$ sin backorders.

\subsection{Variables de interés}
\begin{description}
  \item[$x(t)$] Nivel de inventario en el tiempo.
  \item[$y(t)$] Cantidad pendiente de entrega.
  \item[$R$] Ingresos acumulados.
  \item[$C$] Costos de pedidos acumulados.
  \item[$H$] Costos de mantenimiento acumulados.
  \item[$\pi = (R - C - H)/T$] Ganancia promedio por unidad de tiempo.
  \item \emph{Fill rate}, unidades perdidas, nivel medio de inventario, número de pedidos.
\end{description}

\section{Detalles de Implementación}
\subsection{Diseño conceptual}
Se implementa en Python una clase \texttt{ContinuousReviewInventory} que maneja un heap de eventos (\texttt{heapq}) con tipos \texttt{ARRIVAL} y \texttt{DELIVERY}. El simulador actualiza el costo de mantenimiento entre eventos y procesa llegadas y entregas según la política $(s,S)$.

\subsection{Herramientas y entorno}
\begin{itemize}
  \item Lenguaje: Python 3.9
  \item Librerías: \texttt{numpy}, \texttt{heapq}, \texttt{matplotlib}, \texttt{pandas}, \texttt{seaborn}
  \item Estructura de proyecto modular:  
    \texttt{src/InventoryCore}, \texttt{src/Analyzer}, \texttt{notebooks/}
\end{itemize}

\subsection{Algoritmo principal}
\begin{enumerate}
  \item Inicializar inventario en $S$, programar primera llegada.
  \item Mientras $t<T$:
    \begin{itemize}
      \item Extraer próximo evento de la cola.
      \item Actualizar costo de mantenimiento $\Delta t \cdot h \cdot x$.
      \item Procesar \texttt{ARRIVAL} (generar demanda, ajustar $x$, posibles pérdidas, quizá ordenar) o \texttt{DELIVERY} (sumar inventario, pagar pedido).
    \end{itemize}
  \item Ajustar costo de mantenimiento hasta $T$.
\end{enumerate}

\section{Modelo Matemático}
\subsection{Definición formal}
\[
N(t)\sim\mathrm{Poisson}(\lambda),\quad D_i\sim G,\quad
(s,S)\!:\;x(t)<s\Rightarrow y=S-x(t),\;t_1=t+L.
\]
\subsection{Ecuaciones de actualización}
Entre eventos $t\to t'$:
\[
H\gets H+h\,x\,(t'-t),\quad
R\gets R+r\min\{D,x\},\quad
x\gets x-\min\{D,x\}.
\]
\subsection{Supuestos y restricciones}
\begin{itemize}
  \item Sin backorders: demanda no servida se pierde.
  \item Lead time constante.
  \item Política de revisión continua.
\end{itemize}
\section*{Próximos pasos}

El desarrollo de este simulador no solo permite representar el comportamiento de un sistema de inventario bajo revisión continua, algo útil para la \emph{vida real}, sino que también habilita un \textbf{entorno flexible para el análisis y la toma de decisiones estratégicas}.

A lo largo de este estudio se han implementado diversos analizadores especializados que permiten explorar diferentes aspectos del sistema. Se invita al lector a experimentar con ellos:

\begin{itemize}
    \item \textbf{InventoryAnalyzer} % 📊
    
    Ideal para explorar políticas de pedido. Permite encontrar tupla(s) $(s, S)$ óptimas mediante búsqueda en malla. Prueba distintos horizontes de tiempo y estructuras de demanda para encontrar políticas robustas.

    \item \textbf{SensitivityAnalyzer} % ⚙️
    
    Úsalo para entender \textbf{qué tan sensible es tu sistema} ante parámetros como la tasa de demanda ($\lambda$) o el tiempo de entrega ($L$). Una herramienta clave para análisis de riesgos y robustez.

    \item \textbf{DemandDistributionAnalyzer} % 📈
    
    Explora el \textbf{impacto de diferentes distribuciones de demanda} sobre el rendimiento del sistema. Ideal para evaluar políticas bajo distintos escenarios de incertidumbre.

    \item \textbf{CostStructureAnalyzer} % 💰
    
    Permite comparar cómo distintas estructuras de costos afectan métricas clave como el nivel de servicio o la ganancia. Fundamental para adaptar el modelo a diferentes realidades empresariales.

    \item \textbf{BootstrapAnalyzer} % 📦
    
    Evalúa la \textbf{variabilidad de las métricas simuladas}. Genera intervalos de confianza y ayuda a verificar la confiabilidad estadística de tus resultados.
\end{itemize}

\vspace{1em}

Cada uno de estos analizadores es una herramienta poderosa por sí misma, pero su verdadero valor se maximiza al usarlos \textbf{en conjunto}. Experimenta, ajusta parámetros y descubre las combinaciones que maximizan tu rendimiento bajo incertidumbre.

\section{Conclusiones}
\begin{itemize}
  \item La política óptima $(20,60)$ maximiza la ganancia promedio bajo los parámetros base.
  \item El sistema es sensible a $\lambda$ y $L$; conviene revisar $(s,S)$ en función de la demanda y retrasos.
  \item La elección de la distribución de demanda y de la estructura de costos impacta significativamente en $\pi$ y nivel de servicio.
  \item El bootstrap confirma la robustez de la estimación de $\pi$.
\end{itemize}
